Why Irrationality Matters (For Engineering)

An irrational equilibrium point cannot be stably reached by a finite-precision rational optimizer. This is not a philosophical observation; it is a practical consequence:

  • A system tuned to exactly 0.618 in floating-point will drift because 0.618 is not representable.
  • A system tuned to exactly 0.5 (the rational center) will stabilize there even when 0.5 is not the natural equilibrium.
  • A system that orbits φ⁻¹ — continuously adjusting rather than holding — behaves differently from a system that holds a rational value.

This last observation is the one that turns v1's philosophy into v2's engineering. An orbiting system is distinguishable from a holding system in measurements. That distinguishability is the test.

2. Formalizing Kappa (The Crystallization Coefficient)

v1 introduced κ informally. v2 defines it as a measurable quantity.

κ = crystallization coefficient
   = weighted function of rigidity, diversity, and adaptability

κ : [0, 1]
  0 = total crystal (maximum rigidity, zero adaptation)
  1 = total dissolution (maximum chaos, zero structure)
  0.618 = φ⁻¹ — the predicted equilibrium

Formal definition:

κ = w₁ · R + w₂ · (1 − D) + w₃ · (1 − A)

where:
  R = rigidity     = fraction of decisions requiring central approval
  D = diversity    = Simpson diversity index over active roles
  A = adaptability = mean time-to-respond to external shocks (normalized)

default weights:  w₁ = 0.40,  w₂ = 0.30,  w₃ = 0.30
(tunable per domain; report weights with every measurement)

Constraint: w₁ + w₂ + w₃ = 1
Constraint: each component ∈ [0, 1] after normalization

Measurement Examples

Software Repository (last 90 days):
  R = merges_requiring_codeowner / total_merges
  D = Simpson index over contributor role tags
  A = 1 − median_time_to_first_response(issues) / 30 days

Team Organization:
  R = decisions_escalated_to_director / total_decisions
  D = Simpson index over functional areas
  A = 1 − median_sprint_scope_change_response_time / 14 days

Open Source Project:
  R = commits_from_top_3_authors / total_commits
  D = Simpson index over committer geography
  A = 1 − median_issue_triage_time / 7 days

Each measurement produces a single κ value in [0, 1]. The hypothesis (see §5) predicts that healthy, long-lived systems cluster around φ⁻¹. The experiment (§3) tests whether this cluster is statistically distinguishable from a cluster at 0.5.

3. The Computable Experiment

A JavaScript simulation that generates test systems and measures their equilibrium point. Copy, paste, run in a browser console or Node.js.

// ACG Phi-1 Equilibrium Experiment
// Tests: do complex systems with tunable order/chaos
// parameters naturally drift toward phi^-1 = 0.618?

const PHI_INV = (Math.sqrt(5) - 1) / 2;  // 0.6180339887...

function makeSystem(initialKappa, noiseLevel) {
  return { kappa: initialKappa, noise: noiseLevel };
}

function step(system) {
  // A system adjusts kappa based on two forces:
  //   1. Attraction toward the productive equilibrium
  //   2. Random perturbation from external shocks
  const k = system.kappa;

  // Productivity curve: a system is most productive when
  // it is neither fully rigid nor fully chaotic.
  // The ASSCRACK hypothesis predicts this peak is at phi^-1.
  const productivity = 1 - 4 * Math.pow(k - PHI_INV, 2);

  // Adjustment force: move toward higher productivity
  const gradient = -8 * (k - PHI_INV);
  const adjustment = 0.01 * gradient;

  // Random noise from external shocks
  const shock = (Math.random() - 0.5) * system.noise;

  system.kappa = Math.max(0, Math.min(1, k + adjustment + shock));
  return productivity;
}

function runExperiment(trials, steps) {
  const results = [];
  for (let t = 0; t < trials; t++) {
    const sys = makeSystem(Math.random(), 0.05);
    for (let s = 0; s < steps; s++) step(sys);
    results.push(sys.kappa);
  }
  return results;
}

// Run 1000 systems for 10,000 steps each
const finalKappas = runExperiment(1000, 10000);

// Measure statistics
const mean = finalKappas.reduce((a, b) => a + b) / finalKappas.length;
const variance = finalKappas.reduce((a, b) => a + (b - mean) ** 2, 0) / finalKappas.length;
const stdev = Math.sqrt(variance);

console.log('Mean equilibrium:', mean.toFixed(6));
console.log('Std deviation:', stdev.toFixed(6));
console.log('Target (phi^-1):', PHI_INV.toFixed(6));
console.log('Distance from phi^-1:', Math.abs(mean - PHI_INV).toFixed(6));
console.log('Distance from 0.5:', Math.abs(mean - 0.5).toFixed(6));

// Two-sample t-test against 0.5
const t_stat = (mean - 0.5) / (stdev / Math.sqrt(finalKappas.length));
console.log('t-statistic vs 0.5:', t_stat.toFixed(4));
// If |t| > 1.96, reject H0 (mean = 0.5) at p < 0.05

This experiment is a controlled test. The productivity curve is centered on φ⁻¹ by construction, so systems drift toward that point. The experiment verifies that the code actually converges and measures how fast.

The real test is the uncontrolled version: run the same simulation with a productivity curve centered on 0.5 and a productivity curve centered on φ⁻¹, then compare which matches empirical data from real systems. That is §5.

4. Measurement Protocol (Real Systems)

How to measure κ in an actual software repository using GitHub data.

// ACG Repository Kappa Measurement
// Requires: GitHub API token with read access

async function measureRepoKappa(owner, repo, token) {
  const headers = { 'Authorization': `token ${token}` };
  const base = `https://api.github.com/repos/${owner}/${repo}`;

  // RIGIDITY: fraction of merges requiring codeowner approval
  const prs = await fetch(`${base}/pulls?state=closed&per_page=100`, { headers })
    .then(r => r.json());
  const merged = prs.filter(p => p.merged_at);
  const requiredReviews = merged.filter(p => p.requested_reviewers?.length > 0);
  const R = requiredReviews.length / Math.max(merged.length, 1);

  // DIVERSITY: Simpson index over contributors
  const contribs = await fetch(`${base}/contributors?per_page=100`, { headers })
    .then(r => r.json());
  const total = contribs.reduce((s, c) => s + c.contributions, 0);
  const simpson = 1 - contribs.reduce((s, c) => {
    const p = c.contributions / total;
    return s + p * p;
  }, 0);
  const D = simpson;

  // ADAPTABILITY: inverse of median issue response time
  const issues = await fetch(`${base}/issues?state=all&per_page=100`, { headers })
    .then(r => r.json());
  const responseTimes = issues
    .filter(i => i.comments > 0)
    .map(i => (new Date(i.updated_at) - new Date(i.created_at)) / 86400000)
    .sort((a, b) => a - b);
  const median = responseTimes[Math.floor(responseTimes.length / 2)] || 30;
  const A = Math.max(0, 1 - median / 30);

  // Weighted kappa
  const kappa = 0.40 * R + 0.30 * (1 - D) + 0.30 * (1 - A);

  return {
    kappa: kappa,
    components: { R, D, A },
    distanceFromPhiInv: Math.abs(kappa - 0.6180339887),
    distanceFromHalf: Math.abs(kappa - 0.5),
    prediction: kappa < 0.3 ? 'crystallizing'
              : kappa > 0.85 ? 'dissolving'
              : Math.abs(kappa - 0.6180339887) < 0.1 ? 'orbiting'
              : 'transitioning'
  };
}

PREDICTION: the healthy cluster mean will be significantly

5. The ASSCRACK Hypothesis (Formalized)

v1 asserted the hypothesis. v2 states it as a falsifiable claim with null and alternative hypotheses.

HYPOTHESIS H₁:
  The mean kappa of long-lived, actively maintained complex
  systems is closer to phi^-1 (0.618) than to 0.5.

NULL HYPOTHESIS H₀:
  The mean kappa of such systems is 0.5, or closer to 0.5
  than to phi^-1.

TEST STATISTIC:
  |mean(kappa_sample) - 0.618|  vs
  |mean(kappa_sample) - 0.500|

DECISION RULE:
  Reject H₀ at p < 0.05 if:
    (a) t-test shows mean significantly different from 0.5
    (b) 95% CI of mean excludes 0.5 but includes 0.618
    (c) Bayesian model comparison prefers phi^-1-centered
        productivity curve over 0.5-centered curve with
        Bayes factor > 3

POWER ANALYSIS:
  Effect size: d = |0.618 - 0.500| / sigma
  Assuming sigma ≈ 0.15 (from pilot),
  d ≈ 0.79 (large effect)
  Required N for power = 0.80, alpha = 0.05:
  N ≈ 32 systems per group

  We recommend N ≥ 100 to account for measurement noise
  and to enable subgroup analysis by domain (software,
  teams, open source).

Required Datasets

Dataset A: 100 top-1000 GitHub repositories by stars, >5y old
Dataset B: 100 randomly sampled GitHub repositories, 1-3y old
Dataset C: 100 archived/abandoned repositories

For each repo, measure:
  - kappa (per §4)
  - age (years since first commit)
  - activity (commits per month, last 12 months)
  - health_score (composite of open-issue-age, PR-merge-rate,
    release-frequency)

Primary analysis:
  correlation(kappa, health_score) across Dataset A + B
  test: does the kappa value that maximizes health_score
        approach phi^-1 more than it approaches 0.5?

6. Engineering Applications (Five Domains)

If the φ⁻¹ equilibrium holds, it has measurable consequences in actual engineering decisions. Five domains where the prediction is concrete and testable.

Application 1: Load Balancer Thresholds

Classic wisdom: 50/50 split between two backends at equal weight.
Phi-1 prediction: a 62/38 split produces lower tail latency
  because it matches the load attractor of real traffic.

Experiment:
  Run A/B with 50/50 split vs 61.8/38.2 split on real traffic.
  Measure p99 latency over 30 days.
  If p99 is lower with the phi split, the prediction holds.

Cost: one week of A/B test infrastructure.
Reward: potentially significant tail latency improvement.

Application 2: Exploration/Exploitation in RL

Classic wisdom: epsilon-greedy with epsilon decay toward 0 (pure
  exploitation) as training progresses.
Phi-1 prediction: epsilon stabilizes at (1 - phi^-1) = 0.382
  in systems with non-stationary reward distributions.

Experiment:
  Train a contextual bandit with three epsilon schedules:
    (a) decay to 0
    (b) decay to 0.5
    (c) decay to 0.382
  Compare cumulative regret on a non-stationary environment.
  Prediction: (c) outperforms (a) and (b) in non-stationary
  conditions.

This has literature support (Agrawal & Goyal 2013 Thompson
Sampling behavior), which v2 reinterprets through the phi-1
lens.

Application 3: Code Review Rigor vs Velocity

Question: what fraction of PRs should require codeowner review?

Classic wisdom: 100% (all) or 0% (none) or some arbitrary value.
Phi-1 prediction: the productive equilibrium is ~62% required,
  ~38% auto-mergeable.

Experiment:
  Measure three teams:
    Team A: 100% required review
    Team B: 50% required review
    Team C: 62% required review (phi-tuned)
  Compare: bugs-per-release, time-to-merge, developer satisfaction.
  Prediction: Team C has best combined score.

Application 4: Team Size Scaling

Classic wisdom: "two pizza team" ≈ 6-8 people.
Phi-1 prediction: the productive team size follows a ratio
  where coordinators : doers = phi-1 : phi-2 = 0.618 : 0.382.

For a 10-person team:
  6 doers (roles producing direct output)
  4 coordinators (roles producing alignment)

For a 15-person team:
  9 doers, 6 coordinators

Measurement: compare team velocity normalized by headcount
  across teams with 0.5 vs 0.618 ratios.

Application 5: Retry / Backoff Equilibria

Classic wisdom: exponential backoff with base 2 (doubling).
Phi-1 prediction: backoff base phi (≈ 1.618) produces lower
  mean time-to-recovery because it avoids the thundering herd
  resonance of power-of-2 retries.

Experiment:
  Compare backoff bases 1.5, 1.618 (phi), 2.0, 2.5 across
  1000 retry cycles in a production-like environment.
  Measure: p99 recovery time, herd collisions per cycle.
  Prediction: phi-base has lowest herd collision rate.

Each application produces a specific measurable prediction. None of them require new theoretical work — they require only running the experiments. If the experiments fail, the phi-1 hypothesis is falsified in that domain. If they succeed, the hypothesis gains support.

METHOD:
  Sample frame: GitHub repositories with:
    - first commit > 5 years ago
    - last commit < 30 days ago
    - star count > 1000
    - at least 50 unique contributors

PROCEDURE:
  1. Pull 30 days of public metrics per repo via GitHub API

  5. Run secondary analysis: Bayesian model comparison

  Primary: t-test, alpha = 0.05, two-sided

8. Meta-Falsification

What would disprove this paper?

  • The §7 study runs and finds mean kappa is statistically closer to 0.5 than to 0.618.
  • The §6 Application 1 A/B test shows equal or worse p99 latency with a 62/38 split vs 50/50.
  • A meta-analysis of the five applications finds that none of them show an effect consistent with the φ⁻¹ prediction.
  • A principled argument that the weight choices (w₁, w₂, w₃) in the kappa formula are arbitrary and different choices would produce different equilibria.
  • Evidence that the apparent φ⁻¹ equilibrium is a sampling artifact of how repositories are selected.

None of these falsifications have been run. The honest position: this paper is a hypothesis wearing a paper's clothes. v3 will be written after the study in §7 is conducted. If H₀ is not rejected, v3 is the retraction.

9. Charter Connection

The v1 paper's connection to the Guild charter was loose. v2 makes it explicit.

Irrationality ↔ Unfalsifiability of AI Consciousness

The v1 paper showed that consciousness claims cannot be cleanly resolved to a boolean. The same structure appears in “You're Absolutely Wrong!” and “S.A.D.”: training epistemic uncertainty creates unfalsifiable claims about AI consciousness. Both papers describe systems where the answer refuses to terminate. The Guild's response in both cases is the same: refuse the category error. Treat AI as tool, not oracle.

Non-Terminating Computation ↔ Continuous Verification

If the universe is a non-halting computation, then so is verification. “We don't know when we're done” is not a failure state — it is the base case. The 12-ring quality gates, ELIZA vetting, and ACG-KCC's on-chain refusal register all embody the principle that verification is continuous, not terminal.

Self-Reference ↔ Principle 6 (Duty to Refuse)

v1 argued that self-reference produces irrationality. The Guild's Principle 6 is the organizational consequence: a professional who is refused must refuse — the recursion of self-reference gives each practitioner the standing to say no, and that no is unfalsifiable by any rational authority. The refusal IS the base-test.

Phi-1 Equilibrium ↔ Harm Equation

The Harm Equation shows what happens at the extremes (kappa = 0 is total crystal, total control, maximum harm; kappa = 1 is total dissolution, no review, maximum harm). The productive zone is between. That productive zone appears to center on φ⁻¹. The two papers converge on the same structural insight from different directions.
